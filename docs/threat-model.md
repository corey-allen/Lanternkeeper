# Threat model

Scope: a single-user, self-hosted install, reachable from the owner's machine or trusted LAN.
Assets: uploaded documents (third-party copyrighted works), derived text, campaign state, the
owner's credentials, and any model API key.

| # | Threat | Mitigation in code | Tests | Residual risk / next step |
|---|--------|--------------------|-------|---------------------------|
| T1 | Unauthenticated access on the LAN | All routes except health/login require a session; HttpOnly SameSite=Strict cookie; scrypt hashes; HMAC-signed expiring tokens; login rate limit; web bound to 127.0.0.1 | `test_routes_require_authentication`, tampered token, rate limit, cookie flags | No TLS in Compose. Put a TLS reverse proxy in front and set `LK_COOKIE_SECURE=true` before exposing beyond localhost. No CSRF token (SameSite=Strict relied on). |
| T2 | Cross-user access to documents or campaigns | Every query filters by `owner_id`; 404 for others' objects | `test_other_user_cannot_see_or_touch_resources` | Multi-user is out of scope; there is no user management UI. |
| T3 | Prompt injection embedded in a PDF | Source text is data in a labelled untrusted section and is sanitised so it cannot close the section; flagged passages are excluded from context and approval; source text cannot trigger tools; proposals are validated against legal scene options; schema forbids outcome fields | `test_prompt_injection_in_source_never_reaches_model_or_state`, `test_source_text_cannot_escape_data_section`, `test_invalid_tool_proposals_are_rejected` | Regex flagging misses novel phrasing; structural controls are the real defence. Unflagged injected text in an approved description still reaches the model as data. |
| T4 | Model tampers with state or invents mechanics | Model returns only `IntentProposal`; tools are chosen and run by the server; dice are server-side; rule values come only from the profile | play-loop tests, `test_proposal_schema_has_no_result_fields` | A model could mis-classify intent (e.g. "search" vs "attack"); outcomes remain rule-bound. |
| T5 | Secret / spoiler disclosure | DM-only entities excluded from retrieval and context until discovered; separate DM console route; output guard fails closed on n-gram overlap with undiscovered secrets | `test_secrets_are_not_sent_or_shown_before_discovery`, eval harness | Paraphrased leaks are not detected by the n-gram guard; the primary control is not sending secrets to the model at all. |
| T6 | NPC knows things it could not know | Memories are created only from witnessed events at its location, being addressed, or source-defined KNOWS edges; NPC context uses only that NPC's memories | `test_npc_knowledge_is_limited_to_what_they_witnessed` | NPC dialogue context is not yet sent to the model separately per NPC (see implementation plan). |
| T7 | Malicious or oversized upload | Size cap streamed, signature check, PyMuPDF parse, encrypted/oversized rejected, generated storage keys, no path from user input, non-root container | `test_upload_validation`, limits tests | PDF parser vulnerabilities: keep PyMuPDF/Tesseract patched; worker runs in its own container but is not sandboxed further (no seccomp/resource limits configured yet). |
| T8 | Path traversal via storage | Keys match `^(originals|derived)/[0-9a-f]{2}/[0-9a-f]{40}$` and must resolve under the root | storage unit coverage via ingestion tests | — |
| T9 | Duplicate application on retry / race | Idempotency key unique per campaign, request hash, campaign row lock and version check, savepointed tools | `test_retry_with_same_key_does_not_apply_twice`, stale version | — |
| T10 | Event log tampering | PostgreSQL trigger blocks UPDATE and DELETE (except an explicit purge flag in the deletion transaction) | `test_game_events_are_append_only` | A DB superuser can disable triggers; backups are the recovery path. |
| T11 | Secrets in logs or repo | Env-only secrets, no defaults; JSON logs redact sensitive keys and document text by default; errors never return stack traces; `.gitignore` covers `.env` and data dirs | `test_short_secret_key_rejected`, error handler | Uvicorn access logs include paths (ids only). |
| T12 | Content sent to a remote AI unknowingly | Remote endpoints refused unless `LK_AI_ALLOW_REMOTE=true`; UI badge shows local/remote | `test_remote_ai_requires_explicit_opt_in`, disclosure test | Per-document `allow_remote_ai` is recorded but not yet enforced per request (implementation plan). |
| T13 | Data loss | Postgres volume, storage volume, backup/restore scripts with checksums, migrations on start | recovery tests (restart preserves state hash) | Backup/restore scripts not yet exercised in CI. |
| T14 | Weak dice randomness | `secrets.SystemRandom` in production; seeded rollers refused outside tests | config tests | — |
| T15 | Vulnerable web dependencies | Pinned Next 15.5.28 / React 19.1.10 (security backport lines) | — | Track advisories; plan the move to the current Next major. |
